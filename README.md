# Остатки сладки

Учебный проект по дисциплине «Технологии разработки программных систем».

Сервис для небольших пекарен: к концу дня пекарня выставляет нераспроданную выпечку наборами со скидкой и окном выдачи, соседи видят предложения рядом, бронируют набор и забирают его по коду, оплачивая на месте. Без переписки и звонков.

## Как устроен репозиторий

```text
.
├── README.md
├── docs/
│   ├── requirements.md      # что строим и для кого: требования с идентификаторами
│   ├── traceability.md      # требование → решение → код → проверка
│   ├── process.md           # как работает команда
│   ├── CHANGELOG.md         # что менялось по версиям
│   ├── tech-debt.md         # записанный технический долг
│   ├── domain/              # модель предметной области: события, контексты, агрегаты, единый язык
│   ├── adr/                 # записи об архитектурных решениях
│   ├── architecture/        # обзор архитектуры и диаграммы
│   └── templates/           # формы документов
└── .github/
    ├── pull_request_template.md
    └── workflows/ci.yml     # проверки документов в конвейере
```

Код сервиса появится с ЛР 3: до этого система проектируется целиком в документах. Конвейер уже проверяет документы: требования без идентификаторов и чисел, полноту записей о решениях.

## Как вносить изменения

1. Возьми карточку в Jira из колонки «Готово к работе» и переведи её в «В работе».
2. Создай ветку от `develop`: `feature/SCRUM-<номер>-<кратко>`.
3. Коммиты и название запроса на слияние начинай с ключа карточки: `SCRUM-12: выдача кода брони`.
4. Открой запрос на слияние в `develop`, заполни чек-лист из шаблона и попроси ревью у второго участника.

Подробности — в [docs/process.md](docs/process.md).
