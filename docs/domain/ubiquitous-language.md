# Единый язык

> Черновик по требованиям ЛР 2А. После сессии моделирования событий раздел «Слова, которые не используются» дополняется найденными расхождениями (Р-1, Р-2…), а термины, которые сессия переименует, меняются здесь до первой строки кода.

Словарь предметной области. Одни слова в разговоре, в документах и в коде. Термин, которого нет здесь, в коде не появляется; термин, который здесь есть, в коде называется указанным именем.

**Границы действия**: термины контекста «Бронирование и выдача», если не указано иное. Колонка «Состояние»: пусто — термин появится в коде уже в ЛР 3Б, с которой конвейер начинает проверять совпадение глоссария и кода (задание `language`); «появится в ЛР N» — войдёт позже, проверка его пропускает.

| Термин | Имя в коде | Определение | Контекст | Состояние |
| --- | --- | --- | --- | --- |
| **Предложение** | `Offer` | Публикация «остатки дня» одной пекарни: описание набора, цены, количество наборов, окно выдачи. **Не** товар витрины: живёт один день | Бронирование и выдача | |
| **Набор** | `Bundle` | Единица предложения, которую собирает пекарня из того, что осталось. Покупатель состав не выбирает | Бронирование и выдача | |
| **Количество** | `bundle_count` | Сколько наборов выставлено в предложении или забронировано в брони | Бронирование и выдача | |
| **Остаток** | `remaining` | Сколько наборов предложения ещё можно забронировать. **Не** нераспроданная выпечка в штуках. Уменьшается при брони, возвращается при отмене покупателем; выдача его не меняет | Бронирование и выдача | |
| **Окно выдачи** | `PickupWindow` | Полуоткрытый интервал `[начало, конец)` в часовом поясе точки выдачи, когда набор можно забрать. В момент «конец» окно уже закончилось | Бронирование и выдача | |
| **Закрытие приёма броней** | `booking_cutoff` | Момент за 15 минут до конца окна выдачи; после него новые брони на предложение не создаются | Бронирование и выдача | |
| **Бронь** | `Booking` | Закреплённые за покупателем 1–3 набора одного предложения с кодом выдачи и состоянием | Бронирование и выдача | |
| **Код выдачи** | `PickupCode` | Шесть знаков из 31 допустимого, без `0`, `O`, `1`, `I`, `L`; уникален среди активных броней пекарни. Покупатель называет его продавцу | Бронирование и выдача | |
| **Выдача** | `issue` | Отметка продавца, что набор по брони передан покупателю. **Не** окно выдачи и **не** точка выдачи | Бронирование и выдача | |
| **Отмена** | `cancel` | Прекращение брони **покупателем** до начала окна; остаток возвращается. Отличается от отмены пекарней | Бронирование и выдача | |
| **Отмена пекарней** | `cancel_by_bakery` | Прекращение брони **администратором** с причиной; остаток не возвращается | Бронирование и выдача | появится в ЛР 6А |
| **Не забрана** | `not_collected` | Состояние брони, окно которой закончилось без выдачи. Наступает по времени, не командой | Бронирование и выдача | |
| **Пекарня** | `Bakery` | Заведение, подключённое к сервису: одна точка выдачи, свои сотрудники | Пекарни | |
| **Точка выдачи** | `PickupPoint` | Адрес и координаты, где пекарня выдаёт наборы; от неё считается расстояние в поиске | Пекарни | |
| **Покупатель** | `Buyer` | Человек, который ищет и бронирует наборы. Слова «клиент» и «гость» не используются | Доступ | появится в ЛР 4Б |

## Слова, которые не используются

| Не используем | Используем | Почему |
| --- | --- | --- |
| Заказ, `Order` | Бронь, `Booking` | В системе нет оплаты и доставки (`C-08`, `FR-24`, `FR-25`); «заказ» обещает и то и другое |
| Резерв, `Reservation` | Бронь, `Booking` | Два слова для одного понятия |
| Клиент, `Client`, `Customer` | Покупатель, `Buyer` | Двусмысленно: пекарня — тоже клиент сервиса |
| Товар, `Product`, пакет, сюрприз | Набор, `Bundle` | Набор — не позиция каталога, а «что осталось»; «пакет-сюрприз» — чужой продукт |
| Сгорела, просрочена, неявка (как состояние) | Не забрана, `not_collected` | Одно состояние; «неявка» остаётся словом для подсчёта в `FR-13`, но не именем состояния |
| Остатки (о выпечке в штуках) | Остаток — о наборах | Иначе «остаток 6» читается и как 6 булочек, и как 6 наборов |
| Скидка (как отдельная сущность) | Сниженная цена | Скидку задаёт пекарня ценой; процента в системе нет |
| `Manager`, `Data`, `Helper`, `Util`, `Info`, `Processor` | Слова предметной области | Появляются, когда классу не нашлось имени |

## Термины других контекстов

| Термин | Контекст | Почему здесь не используется |
| --- | --- | --- |
| Сотрудник, администратор, продавец (`StaffMember`, `admin`, `seller`) | Пекарни | В бронировании нужен только идентификатор сотрудника и право на действие |
| Учётная запись, вход | Доступ | Задача общего назначения; способ — `ADR-0004` |
| Подписка, напоминание, подключение к боту | Уведомления | Бронь не зависит от доставки сообщения |
| Итоги за период | Итоги | Суммы за период, а не состояние сейчас |
| Продажа в зале, чек | Касса пекарни | Вне системы: раздельные пути |

## Проверка «на три совпадения»

_Колонка «В расшифровке» заполняется после сессии._

| Термин | В расшифровке | В агрегатах | В требованиях | Результат |
| --- | --- | --- | --- | --- |
| Остаток | — | `remaining`, инварианты И-1, И-4, И-5 | `AC-01.1`, `AC-03.1`…`AC-03.3`, `AC-06.1`, `NFR-04` | Два места из трёх; после сессии — третье |
| Окно выдачи | — | `PickupWindow` в `Offer` и `Booking`, И-3, И-8…И-10 | Общие правила времени, `AC-05.4`, `AC-07.4` | Два места из трёх |
| Не забрана | — | `BookingStatus`, И-10, `BookingNotCollected` | `FR-07`, `AC-05.3`, `AC-04.5` | Два места из трёх. В требованиях встречается и «невыданная бронь» — описательно, не как имя состояния; расхождения нет |
