# 2. Python 3.13 и FastAPI для серверной части

- **Статус**: предложено
- **Дата**: 2026-11-06
- **Участники**: Иванов Дмитрий (запись), Кобелев Владислав (подтверждение в ревью)

## Контекст

Нужен язык и каркас серверной части на весь семестр. Язык задан кафедрой на поток (`C-01`); запись фиксирует, подходит ли он этой системе, что из выбора следует и при каком условии выбор стал бы неверным.

Что потребуется от серверной части по требованиям: обработка запросов покупателей и кабинета пекарни, работа с базой с конкурентными изменениями остатка (`NFR-04`), асинхронная обработка уведомлений через брокер (`C-10`, `FR-08`, `FR-09`), обращение к внешним службам координат и MAX, описание контракта API (ЛР 4Б).

## Движущие факторы

- `C-01`: язык задан кафедрой — выбор не свободный, но запись нужна, чтобы условие пересмотра было названо
- `C-04`: команда из двух человек на один семестр — объём, который реально освоить, важнее скорости исполнения
- `NFR-07`: прогон тестов не дольше 60 секунд, установка — не больше 5 команд
- Контракт API понадобится в ЛР 4Б — предпочтителен каркас, формирующий описание OpenAPI сам
- `C-10`: асинхронная работа с брокером и внешними службами — нужна асинхронность без отдельной библиотеки-основы
- `NFR-01`: 95 % запросов списка рядом быстрее 300 мс при 200 предложениях и 10 запросах в секунду — **не различает варианты**: при таком объёме все три подходят с большим запасом

## Рассмотренные варианты

| Вариант | За | Против |
| --- | --- | --- |
| **Python 3.13 + FastAPI** | Задан кафедрой; проверка данных моделями и описание OpenAPI из коробки; асинхронность встроена; оба участника знают язык с первого курса | Скорость исполнения ниже; ошибки типов ловятся только отдельным инструментом |
| Go + net/http | Высокая скорость; статическая типизация; один исполняемый файл | Описание API и проверка данных пишутся руками; язык новый для обоих участников — уходит время, которого при `C-04` нет |
| Kotlin + Spring Boot | Сильная типизация, зрелая экосистема, OpenAPI через библиотеку | Тяжёлое окружение и долгий запуск — прогон тестов за 60 секунд (`NFR-07`) трудно удержать; на занятиях курса не используется |

## Решение

**Python 3.13 + FastAPI.** Определяющий довод — `C-04`: проверка данных, описание API и внедрение зависимостей даются каркасом, а не пишутся командой из двух человек самостоятельно. Решение кафедры совпадает с тем, что выбрали бы и без него.

## Последствия

**Положительные.** Модели `pydantic` служат и проверкой входных данных, и описанием OpenAPI (ЛР 4Б). Асинхронные обращения к базе, брокеру и внешним службам — без дополнительной основы (ЛР 6А). Подставные реализации внешних служб в тестах пишутся просто — это нужно для `AC-02.4`, `AC-08.4`.

**Отрицательные.** Проверка типов — отдельный этап конвейера (`mypy`); без него аннотации остаются документацией. Конкурентная правильность остатка (`NFR-04`) обеспечивается не языком, а базой: асинхронный код сам по себе от состязания запросов не защищает. Для задач, чувствительных к скорости исполнения, язык не подошёл бы — в объёме курса таких нет.

**Что пересмотрит решение.** Требование обрабатывать тысячи запросов в секунду на одном экземпляре; необходимость поставлять систему одним исполняемым файлом без среды исполнения; отмена решения кафедры.
